# tokyo-ckan-stac

A static STAC catalog for 東京都オープンデータカタログ, the CKAN site at
<https://catalog.data.metro.tokyo.lg.jp/> where the Tokyo Metropolitan
Government, its bureaus and 61 of its municipalities register open data.

CKAN already has an API. What it does not have is a place or a time for any
dataset, so a question like "what is there about 港区 for 令和5年度" has to be
answered by reading titles. This catalog derives both, says on every Item what
they were derived from, and publishes the whole catalog as two Parquet tables
so such a question is one query.

It is a mirror, not a source. The files stay on the publishers' servers; only
the metadata lives here.

## Use it

<https://stac.yuiseki.net/tokyo-ckan/catalog.json>

Browsable with nothing installed:
<https://browser.moregeo.it/external/stac.yuiseki.net/tokyo-ckan/catalog.json?.language=ja>

Every dataset whose publisher covers Tokyo Tower, with DuckDB 1.5.5:

```sql
install spatial; load spatial;
select organization_title, title, start_datetime, datetime_basis
  from 'https://stac.yuiseki.net/tokyo-ckan/items.parquet'
 where ST_Intersects(geometry, ST_Point(139.7454, 35.6586))
   and datetime_basis in ('resource-name', 'dataset-title')
 order by start_datetime desc
 limit 20;
```

Every CSV file whose columns CKAN knows to include 緯度:

```sql
select organization_title, item_title, title, href
  from 'https://stac.yuiseki.net/tokyo-ckan/assets.parquet'
 where list_contains(columns, '緯度');
```

Which shared datasets actually converge on one set of columns:

```sql
select family, standard_dataset_no, organizations, headers_checked,
       dominant_layout_share, unique_layouts
  from read_csv('https://stac.yuiseki.net/tokyo-ckan/families/summary.csv')
 order by dominant_layout_share desc;
```

A family is a dataset name that five or more publishers use. For each, the
first header row of every member's CSV was read.
`dominant_layout_share` is the fraction of the members whose header could be
read that match the most common header exactly; members that could not be
read are left out of both sides. dominant_layout_share measures observed
header convergence within a family, not compliance with an external standard
or semantic equivalence.

## What maps to what

| CKAN | STAC |
|---|---|
| organization (95) | Collection |
| dataset (9,698) | Item |
| resource (83,821) | asset |
| group (分類) | `tokyo:categories`, and the 分類別 tree |

Counts are as of the 2026-09-23 harvest.

## What is derived, and from what

- Time. In order: periods named in the file names (令和4年度 is 2022-04-01 to
  2023-03-31 in Tokyo), then in the dataset title, then the `created` date
  the publisher gave the files, then the date the CKAN record was created.
  `tokyo:datetime_basis` says which. Only the first two are about the data.
- Place. The publisher's area, from 国土数値情報 N03 行政区域 (2026): a
  ward's datasets get the ward, a bureau's get the whole of Tokyo.
  `tokyo:footprint_basis` says which. Tokyo is a MultiPolygon of rectangles,
  one per island group, because one rectangle would run from 沖ノ鳥島 to 奥多摩.
- Size. Not derived. CKAN's `size` is rounded down to a KiB and is published
  as `ckan:size`; `file:size` is left out until measured.

The consumer-facing guide is [catalog AGENTS.md](https://stac.yuiseki.net/tokyo-ckan/AGENTS.md),
generated by `src/tokyo_ckan_stac/docs.py` with the counts of the build.

## Build it

Python 3.12 with pyarrow, geopandas and pytest.

```bash
make packages     # every record from the CKAN API: ten requests
make footprints   # N03 東京都, one 13 MB download; the output is tracked
make datastore    # column names of 11,668 DataStore resources; hours, resumable
make build        # offline, seconds
make validate
make start        # browse it locally in STAC Browser
```

`make datastore` is optional. Without it the build has no `table:columns`.
